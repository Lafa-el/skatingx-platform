# ADR-010: 比赛视频 → 分析（深链与只读上下文横幅）

| 字段 | 值 |
|---|---|
| 状态 | **已通过设计评审（2026-10-30），先于代码写好，随联动 ④ 的实现提交。** |
| 日期 | 2026-10-30 |
| 分支 | `migration/race-day-video-to-analysis` |
| 依据 | `docs/design/race-day-linkages.md` §2.d；ADR-001 D4 / D5 / D6；AGENTS.md「Privacy and video analysis」 |
| 不做 | 不改 `firestore.rules`、`RaceVideoRef`、比赛日录入流程（成绩、赛程、名单、视频的表单、校验、确认语义）、分析流程与保存；不上传视频；不新增云函数与依赖；不把总结卡接入个人最好；不改 legacy 仓库。 |

## 1. 与 ADR-001 的关系

ADR-001 D4 把视频分析列为 Phase 0 的非目标：「若将来要在比赛视频上提供，需要自己的设计、用户明确选择和 ADR」。D5 同样把成绩与分析隔开。

④ **不是视频分析本身**，也不改变上述要求：

- 它只加两样东西：视频页上一个用户主动点击的链接，和分析页上一条只读的上下文横幅。
- **不读任何视频字节。** 横幅只显示视频记录里已有的文字（名称、「存在哪」、外链）。外链是别人的网站，应用不加载它、不探测它。
- 分析本身仍是分析页现有的流程：用户自己下载或找到文件，用现有的文件选择框选择，本地处理，不上传。这正是 D4 要的「用户明确选择」，一步也没有被自动化。
- 横幅不写任何数据；保存分析记录的代码一行不改，所以记录里没有比赛关联。

因此本 ADR 不取代 ADR-001 的任何条款，只记录「视频页到分析页的入口」这一件新增能力及其边界。D4 的另一条同样保留：比赛视频页不得把「收集视频」描述成分析、AI 或生物力学（见 2.7，对 `raceDay.videos.intro` 的改写以此为准）。

## 2. 决定

### 2.1 深链形态

`/analysis/biomechanics?raceVideo={eventId}.{videoId}`

- 参数只含两个 id，用一个 `.` 连接。`isValidRaceDayId` 只允许小写字母、数字和连字符（最长 64），不含 `.`，所以按唯一的 `.` 可无歧义拆开。
- 不带外链、不带名字、不带运动员信息（不带 `rosterId`，也不带 `raceId`；赛程行从视频记录里的 `raceId` 读出）。
- 构造与解析是两个纯函数（`packages/skating-domain/src/race-video-link.ts`）：`raceVideoAnalysisHref(eventId, videoId)`（id 不合法时返回 `null`，列表渲染不抛错，该条不显示入口）与 `parseRaceVideoLink(raw)`。解析要求恰好一个 `.`、两段都通过 `isValidRaceDayId`，否则返回 `null`；URL 里其他参数忽略。入口与横幅共用它们，两边不会各写一份格式。
- 该参数是**不可信输入**：任何人可以手写任何值。id 只用来在**当前登录用户自己的子树**里查找，不会跨用户读取，也没有被拼进路径之外的任何地方。

**要如实说明的一点：id 是名称的 slug。** `createRaceDayEntityId(label, suffix)` 用标签的 ASCII slug 加后缀生成 id（例如 `1000m-final-a-xufrl8`、`2026-buffalo-short-track-championships-rpm6w8`）。所以「URL 只带两个 id」不等于 URL 里没有任何由名称派生的文字：事件名和视频名里的英文单词会出现在 id 里。若用户把运动员姓名写进了视频名称，姓名的 ASCII 形式也会出现在 URL 里。我们不改 id 的生成（那属于比赛日录入流程），因此记录风险并给出缓解：

- 外链用 `noopener noreferrer`，且分析页不加载任何第三方资源，URL 不会通过 `Referer` 带出去；
- 深链只在用户自己的浏览器地址栏和历史里；应用不把它写进日志或埋点（横幅的错误日志只写错误码）；
- 分析页本来就没有分析统计上报。

### 2.2 入口（视频页）

- 每条视频记录一个「去分析」链接，在编辑、删除按钮旁。非确认删除状态下显示，与现有按钮同一处。
- 入口在视频页的 `ProGate` 里面。非 PRO 用户看不到入口，也不会挂载任何视频监听（`ProGate` 的既有注释与行为）。**不新增任何 `isPro` 写入。**
- 链接带一段仅供读屏的后缀（视频名称），避免一排同名「去分析」无法区分。

### 2.3 横幅（分析页）

位置：`AnalysisBiomechanicsPage` 在 `<BiomechanicsPage />` **之上**渲染一个横幅入口，不修改 `BiomechanicsPage` 本身。

先过的门，依次且**每道都在任何读取之前**：

1. `isRaceDayEnabled()` 为假：不渲染横幅入口，不下载横幅代码，不读。开关是构建期常量，关闭时这部分代码在构建中整体消失。
2. URL 里没有 `raceVideo`，或 `parseRaceVideoLink` 返回 `null`（格式非法）：无横幅，页面照常。
3. `useIsPro()` 加载中、读失败或不是 PRO：无横幅，不读，页面照常。
4. 以上都通过，才懒加载横幅并订阅数据。

这些是**体验门，不是安全边界**，沿用 ADR-001 D4 的口径：`isPro` 在 `settings/main` 里客户端可写；规则不变，属主本来就能读自己的比赛日数据。门的目的是让非 PRO 用户手输深链时看不到 PRO 页的内容，也不产生多余读取。

读取：`firebase-client` 的 repository 只有列表订阅，没有单文档读取。新增单文档读取超出本任务范围，所以用现有订阅：

- 视频记录：订阅该事件的 `videos` 列表，按 `videoId` 在内存里取一条；
- 赛程行（项目名）：订阅该事件的 `races` 列表，按视频记录的 `raceId` 取一条；
- 事件（事件名）：订阅事件列表，按 `eventId` 取一条。

至多 3 个监听，列表都很小（ADR-001 D6：每个赛事不到约 50 文档）。三者都在横幅卸载时释放。

**任一读不到 → 无横幅，不报错，不阻断分析**：事件、赛程行或视频记录不存在；某份读取失败；视频记录里的 `raceId` 对不上。读取失败只写一条日志，内容是错误码，不含任何记录内容。加载中同样不显示（不闪、不占位）。

### 2.4 横幅内容

只读，不含任何按钮或表单：

- 比赛（事件名）、项目（赛程行的项目名）、视频名称；
- 「存在哪」：`storedWhere` 有值才显示；为 `null` 就整行省略，不写「未填写」之类的占位。生产里 7 条视频记录的 `storedWhere` 全部为 `null`，这是常态而不是异常；
- 外链：与视频页同一条校验（`checkExternalUrl` / `externalUrlHost`）。
  - 通过：渲染 `<a target="_blank" rel="noopener noreferrer">`，链接文字只显示主机名，与视频页一致；
  - 不是普通 http(s)（`urlInvalid`）：只显示原文，**不**成为链接；
  - 含用户名口令（`urlHasCredentials`）：只显示一句通用说明，**不回显**链接内容，也不成为链接；
  - 没有外链：整行省略；
- **「待确认」标记**：事件或赛程行的 `verification` 为 `pending` 时，在对应文字旁加标记，沿用 ②③ 的做法。依据是 AGENTS.md「未经核对的业务数据必须显式标记为待确认」。视频记录没有 `verification` 字段，不加。
- 一行说明文字：这是你记录的视频信息；请用下面的文件选择框自己选择文件；分析在本机完成，不上传。措辞不使用「AI」「生物力学」之类的描述（那是分析页自己的内容）。

### 2.5 选择文件之后

与普通分析完全一致：用户用页面现有的文件选择框选，本地处理，不上传。保存分析记录时**不带**比赛关联，不持久化对象 URL（`BiomechanicsPage` 在卸载时释放对象 URL，本 ADR 不动它）。横幅与分析流程没有任何共享状态。

### 2.6 打包

横幅的代码（含对 `race-day` repository 订阅函数的静态引用）放在一个 `React.lazy` 块里，只有过完 2.3 的前三道门才下载。已有的教训（ADR-009 §7、②③）：静态引用 repository 订阅函数或比赛日输入校验会把约 24 kB 带进所在的块。本 PR 在描述里记录各块的前后体积（开关开、开关关各一份）。

### 2.7 文案

- 视频页入口的文案放在比赛日文案包（`raceDay.videos.item.analyze`）；分析页横幅文案放在分析文案包（`analysis.raceVideo.*`）。两包互不引用。
- **改写 `raceDay.videos.intro`。** 现文写「本应用不会上传、播放或分析视频文件」，旁边出现「去分析」链接后这句话变得误导。改为：本页只记录视频放在哪里，不上传、不播放；要分析，请去分析页自己选择文件，分析在本机完成。改写保持 D4「不把收集描述成分析」的要求：本页仍不做分析，只指路。

## 3. 备选与代价

| 备选 | 为什么不选 |
|---|---|
| 在分析页直接播放外链视频 | 跨域取不到像素，无法分析；还会把用户填的外链当成可信来源去加载 |
| 把视频字节上传到存储再分析 | 违反「视频不上传」的隐私默认，需要独立的数据处理设计 |
| 复制元数据到分析页 / 建分析草稿 | 没有落点：分析没有草稿概念，记录只在做完后一次性保存 |
| 保存分析记录时带比赛关联 | `validBiomechAnalysisRecord` 的 `exactKeys` 把键写死，要存必须改 schema 和规则，属于另一份设计 |
| 横幅只读视频记录，不读赛程和事件 | 设计稿要求显示比赛和项目；只靠视频记录显示不出事件名与项目名 |
| 在 repository 加单文档读取 | 超出范围；列表订阅已足够，数据量小 |
| 把外链原样作为链接显示 | 违反 ADR-001 D4 对外链的口径（只有普通 http(s)），且含口令的链接会被回显 |

代价：用户要自己再选一次文件（一步额外操作），这是不上传视频的直接后果；横幅为了取项目名与事件名，最多多挂 3 个小监听，且只在深链打开时。

## 4. 已知边界

- 横幅是上下文，不是校验：它不检查用户选的文件和这条视频记录是否是同一段视频，也不会因此阻止或影响分析。
- 事件、赛程行被删后，旧深链（书签、历史记录）打开时没有横幅；这是设计行为，页面可正常使用。
- 视频记录的外链失效或被改动，横幅显示的是记录里当前的值。
- 深链里的 id 含名称派生文字（见 2.1），已如实记录。
- 生产核对（2026-10-30，只读）：`videos` 子集合共 7 条，全部在 `raceDay/{eventId}/videos` 之下，7 条都能找到对应赛程行和事件；7 条的外链都是普通 http(s)，`storedWhere` 与 `note` 全为 `null`。因此横幅在真实数据上能构造，且「存在哪」省略这条路径是真实会走到的。审计脚本只用 `get()`，没有写入；报告在仓库之外。

## 5. 回滚

- **代码：** revert 本 PR。入口与横幅消失，`raceDay.videos.intro` 恢复原文。
- **数据：** 本 PR 不写任何数据，没有需要清理或回退的东西。
- **关闭开关：** `VITE_FEATURE_RACE_DAY` 关闭后，视频页路由重定向到总览（既有行为），分析页没有横幅、没有新增读取。

## 6. 验证

- 纯函数单测（`race-video-link.test.ts`）：构造与解析往返；缺失、空串、没有 `.`、多个 `.`、大写、下划线、超长、空段、多余参数都返回 `null`。
- hook 与横幅测试：开关关闭不订阅；非 PRO、PRO 加载中、PRO 读失败不订阅；非法 id 不订阅；至多 3 个监听且卸载全部释放；任一读不到、读失败、`raceId` 对不上时不渲染；内容正确（含「待确认」）；外链只在普通 http(s) 时成链接，非 http(s) 只显示文字，含口令的不回显；`storedWhere` 为空时省略。
- 「不写」保护：测试里的 `firebase-client` mock 只提供读函数，任何写调用都会因未定义而失败。
- 视频页测试：入口 href 只含两个 id；非 PRO 看不到入口，也没有挂载监听。
- 分析页既有测试不改：横幅入口在开关关闭时不渲染，既有测试没有 Router 也能跑。
- 截图证据：`docs/design/evidence/race-day-video-to-analysis/`（中英文、手机与桌面、无横幅的几种状态）。
- 门禁：`lint`、`typecheck`、`test -- --run`、`build`（开关开与关）、`test:rules`。规则文件不动。
