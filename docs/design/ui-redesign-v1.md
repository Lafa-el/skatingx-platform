## 正文（粘贴给 Cursor）

### 0. 背景与目标

SkatingX 全 app 界面改版 v1.0。设计已定稿（见附件截图：设计稿 artifact「SkatingX 界面设计方案对比」，A 方案为主系统、B 方案用于内容页），本次工作是**纯视觉/交互层重做**：把设计稿落地为代码，不改变任何业务逻辑、数据模型、路由结构和文案语义。

### 1. 设计规范（定版，不可自行发挥）

**方向**：A · Trackside Precision（场边计时牌风）做主系统；B · Ice Editorial（杂志排版风）用于内容型页面；C · Performance Lab 的高密度只留给未来教练端，**本次不实现**。

**配色**（以截图为准，色值如下）：
- 深海军蓝 `#081C33`：导航、标题、结构压底
- 焰橙红 `#FF3E2C`：主色——主操作按钮、选中态、关键数字、进度条
- 动能橙 `#FF9E1B`：与焰橙红做能量渐变，用于"下一场"卡片、头像
- 暖冰白 `#FFF1E8`：页面底色
- 电光蓝 / 冰面蓝退场，不再作为主色使用

**Logo 规则**：
- 火焰 logo：我所有 App 的统一标识，**只出现在 App 图标位**，本体蓝紫渐变保持原样，不要改色
- 滑手 logo：SkatingX 品牌 logo，用于品牌露出位置
- 如实处理：橙红是本版新引入的主色，不要声称它来自 logo

**青少年活力处理**（设计稿特征，必须还原）：
- 斜体大数字（计时牌速度感）
- 贴纸式状态标签
- 加大圆角
- Hero 区橙红斜切速度条

**覆盖页面**（6 类，桌面 + 手机两套）：
今天 / 训练 / 分析 / 日志 / 比赛日 / 设置。截图中有哪一屏，代码就还原哪一屏，不要自己加屏、减屏或改布局。

> 以上一句已被下面「附录 A」的决定收窄：日志屏本次不做，其余屏以附录 A 为准。

### 2. 不可触碰清单（红线）

- legacy 仓库 `blaze-skate-training` / `blaze-skate-analysis`：一律不动
- Firestore 数据模型、`firestore.rules`、`firestore.indexes.json`、`packages/schema`：不动
- Race Day 业务逻辑（时间严格解析、时区转换、PRO 门、验证规则、待确认标记语义）：**只换皮，不改逻辑**；`isPro` 仍是客户端标记，不做服务端 entitlement
- 功能不增减：不加按钮、不删入口；文案语义不变，只做视觉重排
- 现有路由结构不变

### 3. 技术约束（沿用仓库既有标准）

- React 19 + Vite + Tailwind v4 + React Router v7，TypeScript strict
- 中英双语 i18n：所有新增/调整的文案走 i18n，不允许硬编码
- 禁止运行时 CDN（字体、图标本地化或走现有依赖）
- 保持现有代码分割结构，不让主包明显膨胀
- 每个阶段结束必须全过：`npm ci`、`npm run lint`、`npm run typecheck`、`npm run test -- --run`、`npm run build`

### 4. 分阶段实施（一次只做一个阶段，每阶段独立小 PR）

- 阶段 0：设计 Token 落地（Tailwind v4 theme / CSS 变量：四色 + 圆角 + 数字字体风格）+ 共享基础组件（按钮、贴纸标签、卡片、进度条）
- 阶段 1：Shell / 导航栏 + 设置页
- 阶段 2：今天页 + 训练页
- 阶段 3：分析页 + 日志页（范围已修正为"分析页换皮"，见附录 A）
- 阶段 4：比赛日 6 个子页（放到最后）

每阶段交付：实现 → 自测 → PR（含桌面 + 375px 手机截图，中/英各一套）→ 等我验收通过再合，再进行下一阶段。**不直接推 main。**

### 5. 每阶段验收标准

- 与设计稿截图逐屏对照：配色、字号层级、圆角、间距一致
- 桌面 + 375px 手机无横向溢出；触控目标 ≥ 44px
- 中/英双语各走一遍，无硬编码文案、无缺失翻译
- 业务行为零回归：以该页面现有功能为准，只换皮

### 6. 报告要求

每阶段报告里写清：改了哪些文件、有没有碰第 2 节红线里的东西、测试与构建结果、PR preview 链接。如缺少素材（logo 文件、字体），先列出来等我提供，不要自己找图替代。

### B.1 对比度计算（WCAG 2.x 相对亮度公式）

| 前景 / 背景 | 对比度 | 用途判断 |
|---|---|---|
| 白 `#FFFFFF` / 焰橙红 `#FF3E2C` | 3.51 | 仅大字（≥24px，或≥18.66px 加粗）可用；小字不达标 |
| 白 / 动能橙 `#FF9E1B` | 2.07 | 连大字（3:1）也不达标。渐变右端不得放白字 |
| 深海军蓝 `#081C33` / 焰橙红 | 4.88 | 小字达标（≥4.5） |
| 深海军蓝 / 动能橙 | 8.30 | 小字达标 |
| 深海军蓝 / 暖冰白 `#FFF1E8` | 15.52 | 正文 |
| 白 / 深海军蓝 | 17.15 | 深色侧栏上的白字 |
| 焰橙红 / 暖冰白 | 3.18 | 仅图形与大字（进度条、关键数字）；**不得用作小字文本色** |
| 焰橙红 / 白 | 3.51 | 同上 |
| 焰橙红 / 深海军蓝 | 4.88 | 深色侧栏上的指示条与图标 |

结论：
- 渐变 Hero 卡片上，右端动能橙一侧**白字不可用**，该卡片上所有文字用深海军蓝；附录 A 中"大数字白字压焰橙红可保留"仅适用于卡片左半的焰橙红段。为避免渐变中段不确定，建议 Hero 卡片大数字同样用深海军蓝（**待确认**）。
- 主按钮：焰橙红填底 + 深海军蓝文字（4.88），不用白字。
- 带"待确认"语义的贴纸标签：现有 amber 体系保留语义，色值在阶段 0 按对比度重新校准。

### B.2 错误色：`#D92D20` 与品牌色色相几乎相同，不能起到"拉开色相"的作用

| 颜色 | 色相 |
|---|---|
| 焰橙红 `#FF3E2C` | 5.1° |
| `#D92D20`（附录 A 举例） | 4.2° |
| `#C8102E`（候选） | 350.2° |
| `#B3123A`（候选） | 345.1° |

`#D92D20` 只是更深一档的同一种红，并没有和品牌色分开。可选：
- `#C8102E`：偏冷的深红，白字 5.88，暖冰白底上文字 5.32。**建议。**
- `#B3123A`：更冷，白字 6.85，暖冰白底上 6.20。

无论选哪个，两者色相差都只有 15–20°，所以**错误状态必须同时带图标与文字**，不能只靠颜色区分。该规则写进阶段 0 的状态组件验收。**待确认**：error token 取 `#C8102E`。

### B.3 导航选中态：深色字压在深色侧栏上看不见

附录 A 规定"选中态导航不用白字填底，改深色字 + 橙红指示条"。这对**手机底栏（白底）**成立；但**桌面侧栏底色是深海军蓝 `#081C33`**，深色字在上面不可读。
