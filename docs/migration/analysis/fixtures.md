# 分析模块去标识化固件清单

状态：清单与验收标准。**本文件不包含视频或关键点文件。** 文件在 ADR-005 批准后的脚手架分支再放进仓库。

禁止：不得使用 Lindsay 的真实训练或比赛视频，不得使用可识别的人脸、姓名、比赛号码或场地。生产 Firestore 里的器材记录也不得导出成本地固件。

每条固件将来包含：一段短视频（或明确的「没有可用解码帧」）、一份关键点快照（可为空）、期望的 `AnalysisFailure` 或 `PoseFrameOutput.readable`。对照基线是 M1 盘点 §8.7 的旧站行为，不是新算法。

| ID | 情形 | 输入 | 旧站行为（验收） |
|---|---|---|---|
| `fx-input-failure` | 输入失败 | 空文件、非视频，或解码不出画面 | 分析按钮保持「请先上传视频」或等价禁用；不调用 Pose；不上传任何字节 |
| `fx-no-person` | 无人 | 有画面、没有人体 | 该帧 `readable: false`，原因 `no-pose`；角度显示 `--`；若正在采样关键帧，记「当前帧没有稳定骨架，目标不可判读。」 |
| `fx-multi-person` | 多人 | 画面里至少两个人，检测会在人之间跳 | Pose 0.5 仍只返回一个人。跳变被拒绝时记「遮挡、多人重叠或目标跳变，当前帧不可判读。」不要求标出每一个人 |
| `fx-low-frame-rate` | 低帧率 | 明显低于常见比赛视频的帧率，或大段重复帧 | 分析仍按 180 ms 节流；单帧失败只跳过该帧，不结束整段分析。不新增「低帧率」专用文案（旧站没有） |
| `fx-cancel-midway` | 中途取消 | 已开始分析后执行「替换或重置测试视频」 | 停止播放、撤销 object URL、清空关键帧和指标。验收时同时记录 Pose 实例是否仍留在内存（旧站不 `close()`，见 ADR-005 §7） |

通过标准：

- 五条都有独立文件名，且文件里没有可识别的真人影像。
- 同一条固件在旧行为测试和新实现上使用同一输入。
- 关键指标差异的允许范围不在本清单里定。那是 M5，由 owner 批准。
- 本清单不授权把固件提交进当前分支。
